# Phase 3 backend delivery — 2026-10-28

## Scope
Only Phase 3 core employee, leave, expense and approval APIs were changed. Phase 4 security hardening, Phase 5 reimbursement/notification workflows, React UI, AI, analytics and deployment were not implemented.

## Changes in this delivery
- Added expense approval routing using active effective-dated `ApprovalRule` records. Matches amount thresholds, country, currency and expense category, and orders multi-level approvals by `approval_level`.
- Resolves manager, named employee or role-based approvers and rejects self-approval or ambiguous equal-ranked rules. If no rules are configured, retains the existing manager fallback.
- Expense submission now creates one approval step per selected level, with immutable step IDs and audit metadata.
- Expense IDs now use `EXP-YYYY-000001` format. PostgreSQL transaction advisory locks serialize API-generated counters per year. Existing IDs in the database are respected.
- Approval inbox hides later-level steps until earlier steps are approved.
- Preserved existing leave, employee and authentication behavior, and the user's updated tests.

## Verification performed
- Python `compileall` passed for backend application source.
- **Automated tests were not run in this sandbox:** `pwdlib` and `psycopg` were missing and network package installation was unavailable. User's earlier `154 passed` result applies to their *previous* local version, not to these new changes.
- PostgreSQL integration and API runtime are **not yet independently verified** for this delivery.

## Run on Windows (from backend with activated virtual environment)
```
set "JWT_SECRET_KEY=your-local-development-secret"
python -m pip install -r requirements.txt
python -m pytest tests -q --tb=short
python -m alembic upgrade head
python -m uvicorn app.main:app --reload
```

## Known limits / future phases
- Expense approval fallback permits manager-only routing if no rules exist; configure rules for strict policy-driven multi-level routing.
- API-generated IDs are sequential but independently generated by the data generator; coordinate reserved ID ranges before importing synthetic data into the same DB.
- Complete Phase 5 reimbursements, notifications and policy administration remain outside scope.
- This archive is not a guarantee of zero runtime defects; perform Windows/PostgreSQL integration tests before treating it as production-ready.
